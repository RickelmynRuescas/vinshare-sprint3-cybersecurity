Custo de correção

Um segredo barrado no pre-commit custa segundos. O mesmo segredo publicado no GitHub exige rotação da chave, auditoria de uso e, no caso da API do WhatsApp, pode resultar em envio de mensagens fraudulentas para os clientes Ford.

Feedback rápido

O desenvolvedor recebe o achado do Semgrep no próprio PR, com linha, regra e sugestão de correção, sem esperar um relatório de auditoria.

Gate automático

Achados CRITICAL e HIGH, ou segredos verificados, bloqueiam o merge e o deploy. A política vira código.

Secret Scanning com Trufflehog

Combina regex (padrões de AWS, Twilio, SendGrid, Meta/WhatsApp, chaves privadas) com entropia, e faz validação ativa: testa a credencial no provedor e marca verified ou unverified.

Segredos críticos no VIN Share: tokens dos canais, JWT_SECRET, chave Fernet da PII e credenciais de infraestrutura.

01 · Pre-commit hook (local)

Roda antes do commit existir: o segredo nunca entra no histórico.

02 · GitHub Actions (pipeline)

Rede de segurança para quem não tem o hook ou usou --no-verify. Varre o histórico do PR e bloqueia o merge.

.pre-commit-config.yaml
# Hooks executados em todo "git commit" no repositório vinshare
repos:
  - repo: local
    hooks:
      - id: trufflehog
        name: TruffleHog — bloqueia segredos antes do commit
        entry: bash -c 'trufflehog git file://. --since-commit HEAD --results=verified,unknown --fail'
        language: system
        stages: ["pre-commit", "pre-push"]

  - repo: https://github.com/semgrep/pre-commit
    rev: 'v1.85.0'
    hooks:
      - id: semgrep
        args: ['--config', '.semgrep/vinshare.yml', '--error', '--severity', 'ERROR']

  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v4.6.0
    hooks:
      - id: detect-private-key
      - id: check-added-large-files   # evita subir dumps .db/.csv com PII
        args: ['--maxkb=5000']

SAST com Semgrep

Análise semântica (AST) do código, sem executá-lo: cursor.execute(f"...") é encontrado mesmo com outros nomes ou formatação. Detecta injeção, desserialização insegura, JWT mal validado, debug ligado.

  • Rulesets oficiais: p/python, p/owasp-top-ten, p/jwt, p/secrets, p/dockerfile.
  • Regras customizadas do VIN Share (.semgrep/vinshare.yml), escritas para riscos específicos do projeto, como os abaixo.
.semgrep/vinshare.yml
rules:
  - id: vinshare-sqlite-fstring-injection
    languages: [python]
    severity: ERROR
    message: Query SQL montada com f-string/concatenação. Use parâmetros (?) no sqlite3.
    metadata: { owasp: "A03:2021 Injection", cwe: "CWE-89" }
    pattern-either:
      - pattern: $CUR.execute(f"...")
      - pattern: $CUR.execute("..." + $X)
      - pattern: $CUR.execute("..." % $X)

  - id: vinshare-unsafe-model-load
    languages: [python]
    severity: ERROR
    message: pickle/joblib.load executa código arbitrário. Carregue modelos só de artefatos assinados (hash verificado).
    metadata: { owasp: "A08:2021 Software and Data Integrity Failures", cwe: "CWE-502" }
    patterns:
      - pattern-either:
          - pattern: pickle.load(...)
          - pattern: joblib.load(...)
      - pattern-not-inside: |
          verify_model_signature(...)
          ...

  - id: vinshare-jwt-no-verify
    languages: [python]
    severity: ERROR
    message: JWT decodificado sem verificar assinatura ou com algoritmo não fixado.
    metadata: { owasp: "API2:2023 Broken Authentication", cwe: "CWE-347" }
    pattern-either:
      - pattern: jwt.decode(..., options={..., "verify_signature": False, ...}, ...)
      - pattern: jwt.decode($T, $K)

  - id: vinshare-pii-in-logs
    languages: [python]
    severity: WARNING
    message: Possível PII (cpf/telefone/email) em log. Use mask_pii() — LGPD.
    pattern-either:
      - pattern: logger.$L(..., cpf=$X, ...)
      - pattern: logger.$L(f"...{$C.cpf}...")
      - pattern: logger.$L(f"...{$C.phone}...")

  - id: vinshare-fastapi-debug
    languages: [python]
    severity: WARNING
    message: FastAPI/uvicorn em modo debug/reload expõe stack traces.
    pattern-either:
      - pattern: FastAPI(..., debug=True, ...)
      - pattern: uvicorn.run(..., reload=True, ...)

Workflow do GitHub Actions

Em cada push/pull_request para main/develop: Trufflehog, Semgrep e IaC scan em paralelo.

  • Job iac-scan (Hadolint + Checkov) valida Dockerfile e IaC (Etapa 2).
  • Build só roda se os três jobs passarem (needs:).
  • Resultado do Semgrep vai em SARIF para a aba Security.
  • Segredos de deploy vêm de secrets.*, nunca do código.
.github/workflows/security.yml
name: VIN Share — Security Pipeline
on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main, develop]

permissions:
  contents: read
  security-events: write   # upload SARIF

jobs:
  secret-scan:
    name: Trufflehog — secret scanning
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0          # histórico completo, não só o último commit
      - name: TruffleHog OSS
        uses: trufflesecurity/trufflehog@main
        with:
          extra_args: --results=verified,unknown --fail

  sast:
    name: Semgrep — SAST
    runs-on: ubuntu-latest
    container:
      image: semgrep/semgrep
    steps:
      - uses: actions/checkout@v4
      - name: Semgrep scan
        run: |
          semgrep scan \
            --config p/python --config p/owasp-top-ten --config p/jwt \
            --config p/dockerfile --config p/docker-compose \
            --config .semgrep/vinshare.yml \
            --sarif --output semgrep.sarif \
            --severity ERROR --error        # ERROR bloqueia o job
      - name: Upload SARIF
        if: always()
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: semgrep.sarif

  iac-scan:
    name: IaC — Hadolint + Checkov
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: hadolint/hadolint-action@v3.1.0
        with: { dockerfile: Dockerfile, failure-threshold: error }
      - uses: bridgecrewio/checkov-action@v12
        with: { directory: ., framework: dockerfile, soft_fail: false }

  build-and-deploy:
    name: Build & deploy (staging)
    needs: [secret-scan, sast, iac-scan]   # quality gate: só roda se os três passarem
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    environment: staging
    steps:
      - uses: actions/checkout@v4
      - run: docker build -t ghcr.io/vinshare/api:${{ github.sha }} .
      - run: ./scripts/deploy.sh staging
        env:
          DEPLOY_TOKEN: ${{ secrets.DEPLOY_TOKEN }}

Pesquisa: SCA e Container Security

Semgrep e Trufflehog cobrem o código próprio; a maior parte do que roda em produção é de terceiros (libs e imagens). SCA e Container Security fecham essa lacuna (tracejado no diagrama).

SCA: Software Composition Analysis

Faz o inventário das dependências (diretas e transitivas) e cruza as versões com bases de vulnerabilidades (CVE, GitHub Advisory, OSV). Também verifica licenças.

No VIN Share: o requirements.txt tem pandas, scikit-learn, FastAPI, Streamlit, python-jose/PyJWT, httpx e outras. Uma CVE em uma lib de parsing JWT ou no Starlette afeta diretamente a API de todas as concessionárias.

Ferramentas: pip-audit (OSV), Dependabot/Renovate (PRs de atualização automáticos), Snyk Open Source, OWASP Dependency-Check.

Onde entra: job paralelo no CI, que bloqueia CVEs CRITICAL com correção disponível, mais um scan agendado semanal, já que novas CVEs surgem mesmo sem mudança no código. Também gera SBOM (CycloneDX) de cada release.

Container Security

A API (FastAPI/uvicorn), o dashboard Streamlit e os jobs de ML rodam em containers Docker. Proteger containers envolve três camadas:

  • Imagem: scan de CVEs de pacotes do SO e Python (Trivy, Grype, Docker Scout); imagem base mínima (python:3.12-slim ou distroless).
  • Configuração: lint do Dockerfile (Hadolint, Semgrep p/dockerfile), usuário não-root, sem segredos em ENV/camadas, HEALTHCHECK.
  • Runtime: filesystem read-only, no-new-privileges, limites de CPU/memória, assinatura de imagem (Cosign) e detecção em runtime (Falco).

Onde entra: logo após o docker build e antes do push para o registry. O Trivy bloqueia CVEs CRITICAL, e o registry só aceita imagens assinadas.
