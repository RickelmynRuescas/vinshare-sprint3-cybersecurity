Criptografia local

PII em repouso: criptografia em nível de campo

Nome, CPF, telefone e e-mail estavam em texto puro no SQLite: qualquer cópia do .db vazava a base.

  • Campos sensíveis cifrados com Fernet (AES-128-CBC + HMAC-SHA256).
  • MultiFernet permite rotação de chave.
  • Chaves no cofre, nunca no repositório.
  • Blind index (HMAC-SHA256) permite buscar por CPF sem decifrar a base.
customer360_hub/models.py (antes)
class Customer(Base):
    __tablename__ = "customers"
    id    = Column(Integer, primary_key=True)
    name  = Column(String)
    cpf   = Column(String, index=True)   # ❌ texto puro
    phone = Column(String)                # ❌ texto puro
    email = Column(String)
customer360_hub/crypto.py + models.py (depois)
import hmac, hashlib
from cryptography.fernet import Fernet, MultiFernet
from vinshare.config import settings

# MultiFernet permite rotação: a 1ª chave cifra, todas decifram
_fernet = MultiFernet([Fernet(k) for k in settings.pii_keys])   # PII_KEYS do cofre

def encrypt(value: str) -> bytes:
    return _fernet.encrypt(value.encode())

def decrypt(token: bytes) -> str:
    return _fernet.decrypt(token).decode()

def blind_index(value: str) -> str:
    """HMAC determinístico: permite WHERE cpf_idx = ? sem expor o CPF."""
    return hmac.new(settings.index_key, value.encode(), hashlib.sha256).hexdigest()

class Customer(Base):
    __tablename__ = "customers"
    id        = Column(Integer, primary_key=True)
    name_enc  = Column(LargeBinary)
    cpf_enc   = Column(LargeBinary)
    cpf_idx   = Column(String(64), index=True, unique=True)
    phone_enc = Column(LargeBinary)
    email_enc = Column(LargeBinary)

Senhas e dados em trânsito

Senhas: Argon2id

As senhas dos usuários do painel (consultores, gestores, admins) usam Argon2id via argon2-cffi, com salt aleatório por usuário e custo de memória alto, o que torna ataques com GPU caros. O MD5 sem salt anterior foi migrado com re-hash no próximo login.

from argon2 import PasswordHasher
ph = PasswordHasher(time_cost=3, memory_cost=65536, parallelism=4)
hash_ = ph.hash(senha)
ph.verify(hash_, tentativa)   # lança VerifyMismatchError

Trânsito: TLS em todo lugar

TLS 1.2+ no gateway, HSTS e HTTPS/mTLS entre os hubs internos (corrige o achado insecure-transport do Semgrep). Na integração do app Ford existente com os hubs usamos certificate pinning, e na telemetria IoT cada TCU tem certificado de cliente próprio.

# nginx / gateway
ssl_protocols TLSv1.2 TLSv1.3;
add_header Strict-Transport-Security
  "max-age=31536000; includeSubDomains" always;
App Ford (existente): o VIN Share não cria um app novo. O app Ford atual consome os hubs, e nessa integração o token de sessão fica no Android Keystore / iOS Keychain, nunca em SharedPreferences/AsyncStorage em texto puro. O cache local dos dados vindos do VIN Share (histórico, Health Score) usa SQLCipher.

Hardening da API

Rate limiting

Sem limite, /auth/login aceitava brute force e /v1/vehicles/{vin}/health permitia enumerar VINs.

  • slowapi com Redis compartilhado entre réplicas.
  • Chave por usuário, por IP ou por device_id (IoT).
  • Login: 5/min e 20/h. Telemetria: 60/min por TCU.
api/ratelimit.py
from slowapi import Limiter
from slowapi.util import get_remote_address

def key_func(request: Request) -> str:
    # usuário autenticado -> limita por usuário; senão por IP; IoT por device
    if dev := request.headers.get("X-Device-Id"):
        return f"dev:{dev}"
    return getattr(request.state, "user_id", None) or get_remote_address(request)

limiter = Limiter(key_func=key_func, storage_uri=settings.redis_url,
                  default_limits=["120/minute"])

@router.post("/auth/login")
@limiter.limit("5/minute;20/hour")           # anti brute force
async def login(request: Request, body: LoginIn): ...

@router.post("/v1/iot/telemetry")
@limiter.limit("60/minute")                   # 1 msg/s por TCU
async def ingest(request: Request, batch: TelemetryBatch): ...

Validação de entrada

Toda entrada passa por Pydantic strict, e o SQL passa a ser parametrizado (corrige o achado de injection da Etapa 1).

  • VIN no padrão ISO 3779: 17 caracteres, sem I/O/Q.
  • Telemetria com faixas físicas plausíveis.
  • extra="forbid" barra mass assignment (ex.: "role": "admin").

JWT seguro

Antes: assinatura não verificada, sem expiração, segredo fraco ("vinshare123") e qualquer algoritmo aceito (alg: none). Depois:

api/auth.py (antes)
SECRET = "vinshare123"                # ❌ fraco e hardcoded

def create_token(user):

        "role": user.role}, SECRET)     # ❌ sem exp

def current_user(token):
    return jwt.decode(token,

api/auth.py (depois)
ALG = "HS256"
def create_access_token(user) -> str:
    now = datetime.now(timezone.utc)
    return jwt.encode({
        "sub": str(user.id), "role": user.role,
        "dealer_id": user.dealer_id,
        "iss": "vinshare-auth", "aud": "vinshare-api",
        "iat": now, "exp": now + timedelta(minutes=15),
        "jti": uuid4().hex,                 # permite revogar
    }, settings.jwt_secret.get_secret_value(), algorithm=ALG)

def decode_token(token: str) -> dict:
    claims = jwt.decode(token, settings.jwt_secret.get_secret_value(),
        algorithms=[ALG],                     # bloqueia alg:none
        audience="vinshare-api", issuer="vinshare-auth",
        options={"require": ["exp", "iat", "sub", "jti"]})
    if redis.sismember("jwt:denylist", claims["jti"]):
        raise HTTPException(401, "token revogado")
    return claims
  • Access token de 15 min + refresh token de 8 h (rotativo e de uso único, em cookie HttpOnly; Secure; SameSite=Strict no painel).
  • Segredo de 256 bits gerado com secrets.token_urlsafe(32) e guardado no cofre. Para os TCUs IoT, avaliamos RS256 (chave pública nos serviços, privada só no auth).
  • Denylist por jti para logout e revogação imediata em incidentes (usada na Contenção).

@app.middleware("http")
async def security_headers(request, call_next):
    resp = await call_next(request)
    resp.headers.update({
        "X-Content-Type-Options": "nosniff",
        "X-Frame-Options": "DENY",
        "Content-Security-Policy": "default-src 'none'; frame-ancestors 'none'",
        "Referrer-Policy": "no-referrer",
        "Cache-Control": "no-store",
    })
    resp.headers.pop("server", None)
    return resp

Implementação

Duas checagens em cada requisição:

  • Permissão do perfil (RBAC), com MFA nas ações críticas.
  • Escopo de dados: a concessionária do recurso precisa estar no escopo do usuário. Isso barra BOLA (API1).

Fora do escopo a API responde 404, para não confirmar que o recurso existe.

api/rbac.py
from enum import StrEnum

class Role(StrEnum):
    CONSULTOR = "consultor"   # (Brigadista)
    GESTOR    = "gestor"
    ADMIN     = "admin"

PERMISSIONS: dict[Role, set[str]] = {
    Role.CONSULTOR: {"customer:read", "customer:read_pii", "vehicle:health:read",
                     "service:write", "message:send"},
    Role.GESTOR:    {"customer:read", "vehicle:health:read", "service:write",
                     "message:send", "campaign:manage", "report:export"},
    Role.ADMIN:     {"customer:read", "customer:read_pii", "vehicle:health:read",
                     "campaign:manage", "report:export", "model:deploy",
                     "user:manage", "audit:read"},
}
MFA_REQUIRED = {"model:deploy", "user:manage"}

def require(perm: str):
    def dep(user: User = Depends(current_user)) -> User:
        if perm not in PERMISSIONS[user.role]:
            audit.warn("authz.access.denied", user=user, permission=perm)
            raise HTTPException(403, "permissão insuficiente")
        if perm in MFA_REQUIRED and not user.mfa_verified:
            raise HTTPException(403, "MFA obrigatório")
        return user
    return dep

def enforce_dealer_scope(user: User, dealer_id: str) -> None:
    if user.role == Role.ADMIN:
        return
    if dealer_id not in user.dealer_scope:        # anti-BOLA
        audit.high("authz.access.denied", user=user, dealer_id=dealer_id,
                   reason="dealer_scope_violation")
        raise HTTPException(404)                    # 404: não confirma existência

# uso no Customer 360 Hub
@router.get("/v1/customers/{customer_id}")
def get_customer(customer_id: int, user: User = Depends(require("customer:read"))):
    c = repo.get(customer_id) or abort(404)
    enforce_dealer_scope(user, c.dealer_id)
    return CustomerOut.masked(c) if "customer:read_pii" not in PERMISSIONS[user.role] else CustomerOut.full(c)

Segurança MQTT/TLS para IoT

Fase 3 do projeto: a telemetria de veículos conectados é a fase 3 da evolução do VIN Share (Batch/Histórico → Comportamental Digital → Telemetria Conectada). O broker abaixo foi especificado antecipando essa fase.

TCUs publicam via MQTT num broker (Mosquitto/EMQX) à frente do iot-ingestor:

  • Somente a porta 8883 (MQTT sobre TLS 1.2+). A 1883 em texto puro fica desligada.
  • mTLS obrigatório: cada TCU tem um certificado próprio emitido pela CA Ford VIN Share Device CA, e o CN do certificado é o device_id.
  • Sem acesso anônimo, e a identidade vem do certificado (use_identity_as_username).
  • ACL por tópico: cada TCU só publica em vinshare/telemetry/{device_id} e só lê os próprios comandos. Um device não consegue ler nem publicar em nome de outro.
  • QoS 1 (entrega ao menos uma vez), com deduplicação por msg_id no ingestor.
  • CRL (lista de revogação) carregada pelo broker: um certificado revogado é recusado já no handshake.
mosquitto/mosquitto.conf
# sem listener 1883: apenas TLS
listener 8883
protocol mqtt
tls_version tlsv1.2
ciphers ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384

# mTLS — CA "Ford VIN Share Device CA"
cafile   /mosquitto/certs/ford-vinshare-device-ca.pem
certfile /mosquitto/certs/broker.pem
keyfile  /mosquitto/certs/broker.key
require_certificate true
use_identity_as_username true      # username = CN = device_id
crlfile  /mosquitto/certs/device-ca.crl  # revogação

allow_anonymous false
acl_file /mosquitto/config/acl

# limites contra flood (API4)
max_inflight_messages 20
max_queued_messages 100
message_size_limit 65536
max_connections 250000
mosquitto/acl
# %u = username = CN do certificado (device_id)
# cada TCU publica só no próprio tópico (QoS 1 no cliente)
pattern write vinshare/telemetry/%u
pattern read  vinshare/commands/%u

# serviço de ingestão (cert próprio, CN=iot-ingestor)
user iot-ingestor
topic read  vinshare/telemetry/#
topic write vinshare/commands/#
publicação no TCU (mock)
$ mosquitto_pub -h mqtt.vinshare.ford.com.br -p 8883 \
    --cafile ford-vinshare-device-ca.pem \
    --cert TCU-9F21AB.pem --key TCU-9F21AB.key \
    -q 1 -t vinshare/telemetry/TCU-9F21AB -f ponto.json

$ mosquitto_pub ... -t vinshare/telemetry/TCU-00A1C3 -f ponto.json

Ligação com a Etapa 3: no incidente do TCU clonado, a ACL impediu que o atacante publicasse em tópicos de outros veículos, e a cota por device limitou o flood. Na Erradicação, a revogação via CRL derrubou o certificado clonado já no handshake TLS, sem mexer nos demais TCUs. Como reforço, passamos a exigir chave privada em elemento seguro (HSM/TPM) no TCU, para que ela não possa ser exportada.

Outras medidas

  • Segredos via pydantic-settings (SecretStr) lidos de ambiente/cofre, com .env no .gitignore e um .env.example sem valores.
  • Rede segmentada: banco e Redis só acessíveis pelos hubs, nunca expostos à internet.
  • Modelos de ML carregados apenas de uma allowlist com hash SHA-256 (corrige unsafe-model-load).
  • Backups cifrados, com retenção definida conforme a LGPD.
  • Dependências com --require-hashes, para evitar pacote adulterado no build.

O projeto usa SQLite, então não existe serviço de banco. O arquivo vinshare.db fica no volume nomeado sqlite_data, montado somente na api em /data.
